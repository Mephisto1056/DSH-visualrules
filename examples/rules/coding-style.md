# 团队编码规范

> 这是 `examples/profile.yaml` 中 `team/coding-style` 规范包的示例文件。
> 复制到仓库的 `.dsh/rules/coding-style.md`，随仓库提交。

## 命名

- 变量与函数使用 `camelCase`，类型使用 `PascalCase`，常量使用 `UPPER_SNAKE_CASE`。
- 文件名与导出的主概念保持一致。

## 结构

- 一个文件只承担一个明确的职责；超过 400 行时考虑拆分。
- 业务逻辑不直接读写环境变量，统一从配置层注入。

## 测试

- 新增行为必须有测试；修 bug 先补一个能复现的用例。
- 单测不依赖网络与真实时钟。

## 评审

- 每个 PR 至少一位非作者批准。
- 数据库、权限、外部回调的变更必须写清回滚方案。
